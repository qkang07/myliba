# 云层全局索引与虚拟节点

本设计将手机、桌面客户端、纯存储进程视为实体节点，将 OpenList 挂载、WebDAV 目录和对象存储命名空间视为虚拟节点。虚拟节点代表**一份实际存储**，不是访问它的网关进程。两个客户端访问同一个 OpenList 挂载时，云层只计算一份副本。

## 数据边界

云层维护三类可复制的非秘密数据，以及独立的秘密数据：

1. **文件目录**：文件 ID、修订 ID、加密清单、密文块 ID。清单中的文件名、明文校验值和内容密钥继续加密保存。
2. **块位置索引**：`blockID -> nodeID[]`。每个位置附带最后验证时间、库存世代与状态（已确认、待验证或失效）。它是查找提示，不是内容真实性证明；读取后仍须验证密文块的 SHA-256，解密时仍须通过 AEAD 验证。
3. **节点目录**：`nodeID -> kind + access`。实体节点的公开访问方式是直连 HTTPS 或存储节点中继；虚拟节点的公开访问方式包含驱动类型、HTTPS 服务地址和专用挂载路径。这里不放密码、令牌、Cookie、带签名的 URL 或厂商授权信息。
4. **访问凭据库**：`virtualNodeID -> credentialVersion + secret`。它完全独立于文件目录、块位置索引和公开节点目录。Hub 保存最完整的一份，节点可以保存自己有权使用的凭据或短期缓存。

示意数据（其中 `access` 只含非秘密配置）：

```json
{
  "file": {"objectId": "...", "revisionId": "...", "blockIds": ["sha256:..."]},
  "placements": {"sha256:...": [{"nodeId": "phone-a", "state": "confirmed"}, {"nodeId": "drive-a", "state": "confirmed"}]},
  "nodes": {
    "phone-a": {"kind": "physical", "access": {"type": "relay", "endpoint": "https://storage.example/cloud/relay/phone-a"}},
    "drive-a": {"kind": "virtual", "access": {"type": "openlist", "url": "https://openlist.example", "mount": "myliba"}}
  }
}
```

实际块 ID 沿用现有的 64 位小写十六进制 SHA-256；示例中的 `sha256:` 仅说明字段含义。节点 ID 必须稳定、唯一，并绑定一个实际故障域。虚拟节点更换访问它的手机或网关时，节点 ID 和副本计数不变；迁移到另一份物理存储时应使用新 ID。

## 读取与写入

单个本地客户端本身就是一个完整的云层。首次使用时，它创建自己的恢复密钥和本地索引，在本机分块、加密、保存和读取，无需 Hub、云层令牌、公网地址或第二个节点。块位置索引可以只有 `blockID -> 本节点 ID`；目标副本数不足显示告警，不影响上传和读取。只有一个故障域时，丢失该设备仍会丢失数据，因此恢复密钥和本地云层目录都需要单独备份。以后加入其他节点，再按相同的节点 ID 和块 ID 同步库存、补足副本。

读取文件时，客户端先从加密清单得到有序块 ID，再从本地索引查每个块的位置。对每个候选节点，先按节点 ID 查公开访问方式。实体节点可直连或经过**存储节点**中继；虚拟节点由本节点的驱动直接访问 OpenList、WebDAV 或对象存储。若缺少虚拟节点凭据，节点经 HTTPS 向 Hub 按虚拟节点 ID 请求，取得后仅保存在本节点的受保护凭据库或短期内存缓存中。Hub 不转发文件块。访问失败时尝试该块的其他位置、标记故障位置并安排库存复核；不能仅因索引声称存在就认定副本健康。

实体云节点连接 Hub 后会公布本机局域网私有地址及持久 TLS 证书指纹。节点获取在线目录后，先使用 Hub 发放的一次性短期授权探测局域网 TLS，再尝试其公开 HTTPS 或 WebRTC 地址。Go 客户端、Go 存储节点和 Android 存储节点均可接收局域网 TLS 请求；Go 与 Android 也都可以发起和接收 WebRTC 云请求。局域网服务默认监听随机端口，实际连通性取决于设备防火墙与 Wi-Fi 客户端隔离设置；Go 可通过 `MYLIBA_CLOUD_LAN_LISTEN` 指定监听地址，或用 `MYLIBA_CLOUD_LAN_DISABLED=1` 关闭。节点管理页显示每个节点上报的到其他节点的探测结果，客户端云层页和 Android 存储界面显示本节点视角；“在线”仅表示已向 Hub 注册，不代表节点之间已连通。

上传时，客户端先加密、计算密文块 ID，再向选中的实体或虚拟节点写入并校验成功响应。只有确认写入后才发布该 `blockID,nodeID` 位置。目标副本数不足时保留成功上传的文件并给出告警，后台继续修复。对同一个 OpenList 挂载的多个访问路径不得计作多个副本。

## 索引收敛与恢复

Hub 聚合节点目录和块位置，供新节点快速发现，但不是唯一索引源。每个参与云层的节点保存文件目录、节点目录和块位置快照；实体节点保有自身实际库存，虚拟节点的实际库存以对应存储命名空间为准。节点重新上线时发布完整库存世代及后续增量变更。其他节点以库存世代和节点 ID 合并位置；仅由对应实体节点或已授权扫描该虚拟节点的节点确认其库存。过期位置先降为待验证，验证失败才移除，避免短暂离线造成误删。

Hub 丢失后，可从任一持有目录快照的节点恢复文件目录和节点目录，再从实体节点及虚拟存储重建块位置。恢复后的索引必须重新验证候选块，不能把旧的在线状态或访问凭据当作仍然有效。Hub 凭据库需要单独备份；节点本地已有的虚拟节点凭据可以在 Hub 不可用时继续使用。缺少凭据时先尝试其他副本并显示可恢复的访问错误。

## 凭据获取与身份

凭据查询以虚拟节点 ID 为键；公开索引接口永不返回秘密。Hub 只向通过云层认证的节点发放其获准访问的虚拟节点凭据，响应禁止缓存并记录请求节点、目标 ID、凭据版本和时间。节点使用系统密钥库或受保护文件加密本地凭据；凭据版本变化、授权失败或撤销时清除缓存并重新查询。OpenList 应使用仅能访问专用挂载的 WebDAV 账号，读取与写入权限按需要授予，下载应由 OpenList 自身代理，以免重定向暴露凭据。

当前云层已使用主人密码配对产生的逐设备凭据；Hub 和直连存储节点都会验证云层访问权限，撤销设备后相应访问失效。虚拟节点的独立权限范围和按需凭据发放尚未实现，因此当前获准参与云层的设备仍属于同一可信集合。凭据放到独立接口可以避免进入文件索引和管理页面，但后续仍需按虚拟节点收窄权限。

## 与当前实现的差距及迁移顺序

当前 Go 客户端通过扫描在线节点的 `/cloud/inventory` 临时形成内存中的块位置映射；Hub 保存节点注册与加密目录，尚未持久化全局块位置。当前 OpenList、WebDAV、S3 后端藏在某个存储网关或 Android 存储服务后面，在节点目录中显示为该网关的 `backend`，而非独立虚拟节点。Android 节点目前可以用手机空间存储云层块，也能选择 OpenList 作为自己的后端，但尚不能按虚拟节点 ID 从 Hub 取凭据并直接读取别的虚拟节点。

迁移时先加入独立的虚拟节点目录和秘密库；再让 Go 与 Android 实现统一的虚拟节点读写接口；随后发布可复制的块位置快照和库存增量。迁移完成前，不要同时把旧网关和它背后的虚拟节点算作两份副本。最后加入虚拟节点级授权，并把管理界面中的虚拟节点故障域与实体节点分开展示。
