## 1. 产品目标与范围

产品应同时解决“保存在哪里”和“如何找到、整理、使用”。云层是文件的保存位置之一；文件夹、标签、检索与预览属于资源库能力，不应依附某台设备是否在线。

两条主流程必须最终闭环：

1. 手机收录文件 → 整理 → 存入云层 → 验证保存 → 释放手机空间 → 搜索并再次读取。
2. 浏览文件夹或搜索 → 标签筛选 → 识别文件及可用位置 → 预览 → 打开或下载。

已明确的需求：跨设备和云层统一检索、结果去重、上传前后分类保留、上传后的文件夹与标签修改同步、Android 本地文件参与检索。以下具体协议、冲突规则和安全保存阈值是本设计的建议默认值，实施时如调整，应同步修改文档和验收用例。

本轮规划不包含多人协作权限、公开分享、个人社交网关、全文/OCR/语义搜索、跨账号内容去重。多节点加速属于后续优化，不阻塞基础检索和手机空间释放。

### 1.1 用户可理解的操作语义

| 操作 | 结果 |
| --- | --- |
| 收录目录 | 建立索引，原件留在原处 |
| 归入文件夹 | 改变资源库分组，不移动磁盘文件 |
| 添加或移除标签 | 更新分类，不修改原件和副本 |
| 存入云层 | 为同一文件版本增加加密内容位置，保留分类 |
| 复制到另一设备 | 增加同一文件版本的位置；另存为独立文件需明确选择 |
| 移除收录位置 | 停止索引该来源，不隐式删除云层文件 |
| 释放本机空间 | 验证保存条件后删除指定本机原件，保留资源库条目 |
| 移入回收站 | 隐藏逻辑文件，可恢复；与位置移除分开 |
| 永久删除 | 删除逻辑引用，之后由安全回收流程清理无人引用的内容 |

文件夹默认单归属、支持层级；标签可多选。磁盘目录和资源库文件夹分开呈现。筛选默认 AND，不引入用户难以预期的隐式 OR。

### 1.2 不可破坏的约束

- 同一逻辑文件不因上传、复制、目录移动或源设备离线而改变身份。
- 分类是独立持久数据；删除某个位置不能删除文件夹、标签和文件名。
- 清空标签、移出文件夹是有效修改，不能被旧快照补回。
- 索引存在、内容完整、当前可读、允许释放本机是四个不同状态。
- 离线文件仍可检索；默认不因不可读而隐藏。
- 未验证内容不能标记为安全保存；索引发布成功不能标记为原件上传成功。
- 无解密权限的纯存储节点只存密文，不承担明文搜索。
- 路径、SAF URI、文件名、大小和修改时间均不能单独作为跨设备文件身份。

## 3. 节点职责与数据流

| 角色 | 职责 | 是否需要资源库解密权限 |
| --- | --- | --- |
| 浏览客户端 | 展示结果、提交整理操作、请求预览 | 本地解密或访问受信任查询端 |
| 查询执行节点 | 解密目录、物化索引、执行检索、解析读取位置 | 是 |
| 文件来源节点 | 发布自己拥有的文件位置，通过资源接口提供内容 | 发布分类需要；仅提供密文则不需要 |
| 纯存储节点 | 保存和转发加密块、报告存储情况 | 否 |
| Hub | 设备认证、目录密文交换、发现与信令 | 否 |

一台设备可以承担多个角色。UI 中“搜索执行节点”和“文件来源范围”不得混为一个选择器。首个可交付版本由 Go 节点承担查询执行；Android 发布本机索引并使用受信任 Go 节点查询。Android 本地完整查询引擎可以后续实现，但查询端不可达时必须显示缓存结果及过期状态。

当前数据流：本地修改 → 同事务写入待同步操作 → 加密发布 → Hub 持久接收 → 查询端拉取、校验、解密 → 同事务应用并推进游标 → 更新查询结果。内容上传是另一条独立任务链，不跟随元数据同步自动发生；远期去中心化方向见 §3.1。

Hub 的目录交换使用密文，不把明文分类和搜索词交给 Hub。现有资源 HTTPS 中继与云块传输是不同路径；不能笼统宣称 Hub 从不转发任何文件字节。

### 3.1 领域边界与架构演进

当前用 Hub 收录目录记录，P1–P5 暂由它集中裁决写入门槛和清理协调，以闭合跨节点一致性与安全回收；实现状态见 §11。**这不是资源库长期依赖中心节点的目标架构。**资源库身份、操作语义、因果合并、快照和成员前沿必须由持钥节点理解并持久保存；Hub 只交换密文和可验证的协议元数据，不拥有明文业务状态。暂由 Hub 承担的全局准入与清理协调要通过明确接口暴露，不能散落在查询、来源和存储节点的各自判断中。

实施时按以下边界确定规则所有者，再让 Go、Android 和 Web 通过协议使用这些规则：

| 边界 | 拥有的规则 | 对外契约 |
| --- | --- | --- |
| 身份与版本 | libraryId、fileId、revisionId、旧 ID 映射及成员 epoch | 稳定身份、显式迁移与版本绑定 |
| 操作与收敛 | 事务 outbox、作者序号、因果合并、冲突与应用前沿 | 不可变加密操作、回执、幂等重放 |
| 快照与回收 | 快照覆盖、活跃成员确认、保留期和引用检查 | 可复核的清理计划；执行时重新校验 |
| 查询与读取 | 解密投影、覆盖状态、实时可读性及版本固定候选 | 分页索引、候选解析和短期读取授权 |
| 交换与传输 | 密文目录交接、发现、信令及内容传输 | 可替换的同步/传输接口；当前由 Hub 和存储节点实现 |

这项拆分先约束接口和状态所有权，再逐步搬移现有代码；不以全面重写作为 P1–P5 的前置条件。尤其要避免把“Hub 已收到”“成员已应用”“内容当前可读”“允许物理删除”合成同一个同步状态。

远期目标是弱化 Hub，使持钥节点能通过多条交换路径直接传播、验证和合并不可变操作与快照；Hub 可以保留为可选发现或中继节点，但不应是唯一目录权威或唯一恢复来源。进入该阶段前，需单独设计设备身份与 epoch 的可验证声明、成员退役的共同确认规则、反熵同步、快照证明及分布式清理授权；这些协议不能仅用当前 Hub 的目录代号或本机时间替代。迁移门槛是断开 Hub 后仍能保存离线写入并最终收敛，旧设备不能复活删除项，且任何节点都不能单独删掉其他活跃成员仍引用的内容。此方向不改变 P1–P5 已实现的代码边界和用户验收归属。

## 4. 数据模型与身份

所有业务实体带 `libraryId`；ID 使用随机不透明值，不包含路径、名称或明文内容摘要。下表为目标逻辑模型，数据库表名可按平台调整。

| 实体 | 关键字段 | 规则 |
| --- | --- | --- |
| Library | libraryId、schemaVersion、keyEpoch | 一个资源库的身份及密钥域 |
| File | fileId、name、currentRevision、lifecycle | 与位置无关，回收后身份保留 |
| Revision | revisionId、fileId、size、contentDigest、verification | 内容不可变；修改产生新版本 |
| Folder | folderId、parentId、name、lifecycle | 文件夹改名不批量改写每个文件 |
| Tag | tagId、key、value、lifecycle | 普通标签可使用固定 key；为键值标签预留统一模型 |
| Membership | fileId、folderId、causalContext | 文件夹归属独立于原件版本 |
| TagAssignment | fileId、tagId、addTokens、removedTokens | 支持并发添加、移除 |
| Location | locationId、fileId、revisionId、nodeId、storageId、resourceRef、state | 路径仅由来源节点解释 |
| Asset | assetId、revisionId、kind、specVersion、locations | 缩略图/视频等派生内容绑定版本 |
| Alias | libraryId、sourceNode、legacyType、legacyId、fileId | 兼容旧 ID、资源 ID、SAF URI |
| Operation | opId、authorId、authorEpoch、counter、context、payload | 幂等同步单元 |
| TransferTask | taskId、fileId、revisionId、stage、checkpoint、error | 上传和释放的可恢复任务 |

### 4.1 身份创建、导入与迁移

首次收录生成 fileId，持久化到本地数据库。重扫相同来源使用 Alias 找回；文件在应用内移动时事务更新位置和别名。外部移动不能可靠关联时先标记待确认，不依据同名自动合并。

Android 当前资源 API 使用 URI 编码 ID，发布器使用节点和 URI 派生的哈希 ID。迁移时为已有记录建立别名映射，保留已发布 fileId 的关联；新收录使用持久身份。`resourceRef` 必须能经来源节点解析到旧资源 API，不允许客户端把 fileId 直接当旧 resourceId。

通过应用复制或存入云层必须携带 fileId 和 revisionId。独立收录的两份同内容文件保持两个逻辑文件，仅提示重复候选；用户确认合并后记录别名和分类合并结果。物理块去重与逻辑合并分开，不能承诺随机加密下的跨库去重。

### 4.2 版本与去重

- 大小和修改时间仅用于扫描变化提示；不作为最终内容相同的证明。
- 扫描产生待验证版本；读取/上传时计算完整摘要并确认文件未在读取期间变化，发布已验证版本。
- 内容摘要留在加密元数据内；revisionId 是稳定不透明 ID，不能每次扫描随机生成新版本。
- 同一 fileId、同一 revisionId 的位置合并。默认展示一个文件卡片，历史版本在详情展开。
- 同一 fileId 出现并发内容版本时显示版本冲突，保留分支；不能凭设备时钟覆盖其中一个。
- 同名不同 fileId 不合并；同文件不同版本不把旧副本当新版本可读位置。

### 4.3 分类的独立性

分类操作针对 fileId，不针对 revisionId 或某个云副本。云清单可带初始分类快照帮助恢复，但已有分类操作优先，不能由旧清单重新覆盖。缺字段表示未知；显式空集合表示已清空，二者必须在迁移和协议中区分。

删除文件夹默认将文件移到“未归组”，保留文件和标签；删除父文件夹需明确包含子文件夹还是调整层级。首期采用包含子文件夹一起删除分组、文件全部保留的确认流程。并发移动到已删除文件夹的文件进入“待处理归组”，保留原操作以便恢复，不静默丢弃。

## 5. 元数据同步协议

### 5.1 持久化与确认

本地业务修改与 outbox 写入必须在同一数据库事务中完成。后台发布器只消费 outbox；完整扫描用于补漏和迁移，不作为正常变更检测方式。操作生成一次 opId，重试复用，不重复产生操作。

每个作者使用持久 authorEpoch 和递增 counter。重装或恢复无法保证计数连续时创建新 epoch；服务端拒绝同一作者序号对应不同内容的记录。接收端以 opId 去重，同事务写 inbox、应用物化状态、推进游标。重复投递、崩溃重试和批次部分成功都不得重复应用。

UI 区分“本机已保存”“待发布”“Hub 已接收”“查询端已应用”。Hub 204 仅表示交接持久化成功；查询端应用确认或查询读取到该 opId 后才能声称在该端可见。没有全设备确认时，不显示“所有设备已同步”。

失败采用指数退避加抖动；网络恢复可提前重试。鉴权失效单独提示重新配对；格式损坏记录隔离并继续其他文件，避免单个坏记录阻塞整库。磁盘满时本地整理事务失败并保留旧值，不能显示成功后再丢失待同步记录。

### 5.2 并发规则

不使用墙上时间决定业务覆盖关系。操作携带作者序号及已观察的因果上下文；实现应采用成熟、可测试的版本向量/点版本向量表达，不自行用时间戳近似。

| 场景 | 合并规则 |
| --- | --- |
| 先改再改，后者观察过前者 | 后者生效 |
| 两端并发添加不同标签 | 两者都保留 |
| 移除已观察到的标签 | 移除对应 add token |
| 离线端同时重新添加同一标签 | 新 token 保留，UI 可说明并发添加；不假装清空具有全局锁 |
| 两端并发移到不同文件夹 | 保留冲突候选，显示“归组待确认”；用户选择生成覆盖全部已知候选的新操作 |
| 文件夹或文件并发改名 | 保留候选，提供可重复的暂定显示顺序并标记冲突 |
| 来源位置被移除 | 仅使该位置失效，分类和其他位置不变 |
| 文件回收与分类编辑并发 | 回收状态优先隐藏，编辑保留，恢复后可见 |

首期可以只允许来源节点编辑分类，但必须禁用其他节点写入口并提示边界。双端编辑入口只能在上述规则、冲突 UI 和乱序测试通过后开放。

### 5.3 快照、删除与离线恢复

快照携带覆盖的因果前沿和 schemaVersion。接收端应用快照后仅重放未覆盖操作；旧快照不能使删除项复活。分别定义 locationRemoved、fileTrashed、fileDeleted，不能用同一个 `Deleted` 表达三者。

日志、tombstone 和无引用块的回收条件必须包含：保留期、快照持久化、活跃成员确认前沿。建议回收站默认 30 天，但天数到期本身不够执行块删除。长期离线设备经明确退役后移出确认集合；再次加入必须取得新 epoch 并完整引导，不能重放旧状态覆盖当前库。压缩尚未实现前宁可保留日志，不提前删除。

## 6. 统一检索与打开

### 6.1 查询索引

查询执行节点维护解密后的本地物化数据库，可使用 SQLite FTS 支持文件名、文件夹路径、标签和来源名称检索。文件夹以 folderId 过滤，标签以 tagId 或规范化 key/value 过滤；同名文件夹不能被误认为同一实体。

默认范围为整个资源库，可切换本机、指定设备、云层、指定文件夹。设备和云层是位置条件，同一文件命中多个位置仍只出现一次。结果提供 total、分页 cursor、queryGeneration、覆盖设备及各自最后应用时间。游标绑定查询条件和索引代次；索引变更导致游标失效时明确要求刷新，不静默漏项。

排序至少支持名称、入库时间、内容修改时间；同值以 fileId 稳定排序。分类修改时间与内容修改时间分开。筛选包括标签、类型、归组状态、是否有云副本、当前可读；“当前可读”默认关闭。标签/类型筛选项计数按去重后的文件统计。

### 6.2 结果与状态

结果返回 fileId、当前版本或冲突版本、名称、分类、预览、位置摘要、同步状态。分别展示：

- 索引新鲜度：最后同步时间、哪些来源尚未同步。
- 内容状态：可读取、来源离线、权限失效、位置待验证、云块缺失。
- 保存状态：完整副本数量及独立故障域数量，最近验证时间。
- 整理状态：待同步或存在冲突。

首次无索引、查询端离线、没有匹配结果、筛选隐藏全部结果使用不同空状态。切换范围保留关键词，并明确提示被清除的不兼容筛选。保存常用查询只保存条件，不保存一次结果。

### 6.3 读取解析

客户端提交 fileId、revisionId 和用途（原件/缩略图/预览）；查询端返回可用候选及短期授权，来源节点通过 resourceRef 解析，不暴露可任意读取的路径接口。

优先尝试匹配版本的本机内容、可达设备、云层完整内容；具体排序可根据网络代价调整。失败时按候选回退，并显示正在连接的来源和失败原因。预览可以单独可读，不能因此将原件标记可用。下载途中校验失败必须中止并尝试其他来源，不能保存损坏文件为完成。

## 7. 目标 API 契约

以下为拟新增契约，不表示现有接口已经支持。落地前补充请求/响应结构、错误码和契约测试；`/api/cloud/files?scope=all` 保留为过渡适配入口。

| 接口 | 关键输入 | 输出或约束 |
| --- | --- | --- |
| `POST /api/library/search` | query、scope、folderId、tags、sort、cursor、limit | 去重结果、total、generation、coverage、nextCursor |
| `GET /api/library/files/{fileId}` | 可选 revisionId | 分类、版本、位置、同步及冲突详情 |
| `POST /api/library/files/{fileId}/resolve` | revisionId、purpose | 授权读取候选或明确不可用原因 |
| `POST /api/library/operations` | opId、context、操作列表 | 本地提交结果及 pending 状态；有序依赖批次原子提交 |
| `GET /api/library/sync/status` | 可选 authorId | outbox、失败记录、各端应用前沿 |
| `POST /api/library/transfers` | fileId、revisionId、目标策略 | 持久 taskId，不返回虚假的上传完成 |
| `POST /api/library/files/{fileId}/release-check` | locationId、revisionId | 可否释放、原因、短期校验凭据 |
| `POST /api/library/files/{fileId}/release` | locationId、校验凭据 | 删除前再次校验并创建/推进释放任务 |

搜索示例：`{"query":"旅行","scope":{"kind":"library"},"tags":[{"key":"主题","value":"家庭"}],"sort":"name","limit":50}`。默认 limit 50，建议最大 200；空 cursor 表示新查询。

统一错误分类：unauthorized、sourceOffline、permissionLost、revisionChanged、conflict、unsupportedSchema、cursorExpired、insufficientReplicas。错误响应包含可恢复建议和 requestId，不包含密钥、令牌或明文路径。

HTTP 请求级校验失败返回相应 4xx；正常并发操作可被接收并产生业务冲突。需要指定基础版本的条件式操作在前置条件变化时返回 409 及当前上下文，不能自动重试覆盖。修改接口支持相同 opId 重试；相同 opId 不同负载拒绝。

这些明文业务 API 只位于本机或经认证、加密传输的受信任查询端。Hub 同步端点继续交换加密操作/快照，不能直接复用明文业务请求存储。

1. 为 LocalLibrary 添加稳定 fileId、revisionId、别名、outbox、接收游标及迁移版本；每次标签、归组、文件夹改名、移除来源与扫描变更均写事务 outbox。
2. 发布器消费有界批次，单条失败隔离，确认落盘后再标记完成；进程退出时不丢失待发操作。保留当前密文重试机制作为传输层基础。
3. 使用适合 Android 限制的持久后台任务调度；前台传输有通知和取消入口。普通索引同步不能依赖永不停止的 20 秒轮询。精确调度方案在实现时按目标 SDK 验证。
4. 应用启动、网络恢复、用户手动同步触发调度；周期全量核对用于发现漏报，不反复计算未变化大文件的摘要。

6. 配对绑定 libraryId、设备身份和密钥域；更换 Hub/资源库时隔离旧队列，不把旧分类发到新库。恢复密钥保存在系统安全存储，日志不得打印。
7. Android 的来源 API 增加受控 resourceRef 解析或稳定 ID 查询映射；验证请求库、版本和访问权限。
8. 设置页面显示索引同步开关、已索引数、待发布数、失败原因、最后接收确认；“发布索引”和“上传原件”使用不同开关与状态。

## 9. 手机上传与安全释放

上传任务状态：`queued → reading → encrypting/uploading → verifying → committed`，任一阶段可进入 retryableFailed、blocked 或 cancelled。committed 要求完整清单和内容验证持久化后发布；预览失败可以独立重试，不伪造原件失败或成功。

读取前后检查来源版本；内容变化则旧上传作为旧版本保留或回收，重新收录新版本，不能把旧清单绑定新版本。断点恢复以已校验块为单位；取消不删除已存在且被其他清单引用的块。

释放任务状态：`checking → eligible → deletingLocal → locationRemoved → completed`。默认仅对用户明确选中的位置操作；首期不提供无人值守自动删除。

建议安全默认值：至少两份完整、可验证的远端保存，位于两个独立故障域，并且恢复密钥已完成可恢复性检查，才允许常规“释放本机空间”。单节点云层可存储和读取，但不满足此默认释放条件。以后如支持降低策略，需独立说明并由用户显式选择，不能将“上传完成”变成默认删除授权。

检查至少包括：

- 固定 fileId/revisionId；原件大小和摘要匹配，删除前再次确认原件未变化。
- 原件全部块可寻址、长度和密文校验通过；至少一条恢复路径完成读回、AEAD 解密和明文摘要校验，另一故障域完成完整块持久性与校验确认。
- 同一物理盘的多个网关、同一虚拟存储的多个入口只算一个故障域；未知故障域不计入独立保存数量。
- 校验凭据绑定位置、版本、策略、验证时间并短期有效；实际删除前复查关键状态，过期重验。
- 元数据与版本清单已在查询端可见；恢复密钥不能只有待删除设备唯一持有。
- SAF 删除成功后才移除本机位置；拒绝/失败保留位置并显示原因。崩溃后核实文件实际存在性，幂等收尾。

本机删除不清理分类，也不删除用于离线检索的最小元数据。释放完成后关闭手机来源，另一端仍能搜索、看到同一分类并从云层读取原件，才算业务验收通过。

## 10. 安全、迁移与兼容

### 10.1 权限边界

目录加密保护 Hub 和纯存储节点不知内容；持有同一库密钥的查询节点可以看到该密钥域内元数据。文件夹密码的 UI 检查不能替代加密隔离。受保护内容在独立权限域设计完成前默认不发布到普通统一索引；此前已发布的数据不能承诺撤回。

设备撤销阻止未来访问和发布；历史持钥设备已取得的明文无法收回。密钥轮换和重新加密属于独立工作，不得用删除一条索引冒充撤权。API 检查 libraryId 和作者权限，不能允许任意设备伪造另一设备的位置报告。

### 10.2 渐进迁移

1. 备份本地数据库并记录 schemaVersion；新增表和别名，不直接重写或删除原始身份。
2. 读取现有 format 3 加密记录，转为带 provenance 的 legacy snapshot。新业务 payload 带独立 schemaVersion；不要未经设计修改现有加密 AAD 或 nonce 规则。
3. 将旧分类快照导入为一次有来源的基线操作，记录导入完成前沿。旧快照之后只能补充位置等被明确允许的信息，不能覆盖新分类或复活删除项。
4. 混合版本期间实行能力协商；已升级资源库的分类写入要求支持新协议。旧客户端可通过适配器只读，无法确保只读时应拒绝连接写接口，而非让两种写入规则竞争。
5. 未知 schema 隔离并提示升级，不按空数据处理。回滚保留数据库备份和操作日志；旧程序不支持新库时以只读导出/恢复路径处理，不强行降级写入。

迁移验收必须覆盖重复运行、半途退出、旧节点重新上线、已有云清单、同名文件夹和显式空标签。稳定身份映射先完成，再开放跨端编辑。

多版本读取（2026-11-08）：一个逻辑文件有多个已索引 revision 时，`resolve` 未指定 revisionId 返回 `revisionChoiceRequired`，Web 与 Android 列表要求先进入版本列表选择下载，避免自动选中的展示版本被静默当作读取版本。当前列表的展示顺序仍按修改时间确定；跨设备因果版本关系及“默认当前版本”的共享决议尚未实现，T04、T16 待用户验收。

当前版本决议（2026-11-08）：新增 `file.version.select` 加密操作及按 fileId 保存的当前 revisionId。Web 详情和 Android 版本列表可明确设为当前版，查询列表优先展示它，`resolve` 未带 revisionId 时也仅在该已选版本仍存在时采用它。未选择时，多版本仍返回 `revisionChoiceRequired`；并发选择保留候选，在 Web/Android 冲突入口由用户重新选择并发布操作，迟到的已观察操作不能复活旧冲突。其他版本不会删除。Android 数据库升至 v16；跨端传播、乱序与真实设备迁移待用户验收。

用途候选（2026-11-08）：`resolve` 候选增加 `readPath`；原件路径固定 revision，缩略图用途只返回设备缩略图路由或确有缩略图资产的云层候选。云层缩略图新增指定 revision 的资产读取路由，避免历史版本被当前资产覆盖。`preview` 仍以匹配版本原件作为回退，独立预览可读性和短期授权令牌尚未闭环；T16 待用户验收。

本轮离线与读取（2026-11-08）：查询端提供按 generation 连续分页的完整离线元数据；Android 按库和查询节点将整代数据写入暂存表后事务替换，离线结果显示缓存时间并将可读性标为未知。Web 只在用户启用且设置本地口令后将 AES-GCM 加密索引写入 IndexedDB。`resolve` 分别列出缩略图、视频预览与原件候选，来源和云层候选携带两分钟的读取凭据；Go/Android 新路由核对库、fileId、revisionId、用途、节点、resourceRef 与有效期，云层指定版本读取也校验凭据。Web/Android 请求头传递凭据并按候选回退。旧受认证直达路径为兼容既有客户端仍可用；视频流尚未换取短期 HttpOnly 会话，完整 SQL facet/覆盖计算和视频预览回退仍缺。T01、T03、T04、T14、T16、分页与性能基线均待用户验收。

离线索引范围补充（2026-11-08）：Web/Android 本地索引键均纳入查询节点与库 ID，Android 在刷新首个分页后核对代次，再事务替换整代数据；旧 Android 索引数据库升级时迁移缓存键。离线排序补齐收录时间，缓存来源和可读性仍仅代表同步当时的元数据，不能当作当前可读证明。T01、T14、T16 与真机缓存迁移待用户验收。

本轮检索与流媒体读取（2026-11-08）：`searchLibrary` 的文件夹/标签 facet 计数（含交叉筛选与零计数保留）、覆盖字段和 cursor generation 改由 SQLite 物化投影（`library_search_meta`/`library_search_current`/`library_search_tags`）计算，稳定排序与 LIMIT/OFFSET 分页在 SQL 执行；当前可读筛选仍走 Go 以叠加实时来源/云块可用性，投影不宣称当前可读。新增 `libraryStreamSession`（用途 original/preview、20 分钟、路径前缀绑定）与 `POST /api/library/files/{fileId}/stream-session` 交换端点：先校验 resolve 读取凭据再签发，本机以 HttpOnly SameSite=Strict cookie 交付、远程经 `X-Myliba-Library-Read` 头携带；`cloud.download`、`cloudVideoPart` 与 `serveLibraryRead` 在凭据出现时按 fileId/revisionId/用途/节点/resourceRef/前缀校验，过期、跨用途、跨资源或版本不符直接 403 而不静默回退，原件用途会话可覆盖预览流、预览会话不能读取原件路由。StreamingVideo/virtualMedia 在云层统一检索视频播放前换取会话并随分段/原片请求携带；Android `previewVideoCandidates` 按 videoPreview 候选逐个校验来源版本后读取预览短片，失败回退现有流媒体。新增 Go 回归覆盖用途/绑定/过期/跨类型不可复用与交换端点；远程 WebRTC 合成响应无法存储 cookie，故远程依赖读凭据头，旧受认证直达路径仍兼容。T16、真机播放、跨端凭据与性能基线待用户验收。

当前进展（2026-11-08）：统一检索已接入 SQLite 当前文件投影、FTS5、SQL 筛选/排序/分页，facet 计数、覆盖字段（lastCatalogAt/sources/sourceLastCatalogAt）与 cursor generation 均由物化投影计算，读取时重新叠加来源和云块可用性，索引变化使旧 cursor 失效；完整离线元数据可按 generation 分页，Android 按库及查询节点原子替换索引，Web 离线索引由用户启用并设置口令后加密落盘。`resolve` 返回版本固定的原件、缩略图和视频预览候选及短期用途凭据；Web 来源视频预览失败后回退流媒体。流媒体可经 `POST /api/library/files/{fileId}/stream-session` 用已校验的读取凭据换取 20 分钟 HttpOnly 会话（远程经读凭据头携带），云层原件/视频分段与来源读取路由按 fileId、revisionId、用途、节点、resourceRef 及路径前缀校验，过期或跨用途凭据被拒绝且不回退；Android 统一检索视频预览按 resolve 的 videoPreview 候选逐个回退并校验版本，失败后回到现有流媒体。缓存与离线结果仍不能视为当前可读，预览可读不推出原件可读；旧受认证直达路径为兼容既有客户端仍可用。T01、T03、T04、T14、T16、分页与性能基线待用户验收；P4 不标记阶段完成。

## 13. 后续开工顺序与完成定义

下一次实施以 §11“下一次编码入口”为可执行清单：先核对工作区与 P1 已实现链路，再按 P2 Hub 写入门槛、P3 安全回收、P4 检索与读取顺序补剩余代码。P0/P1 的早期任务描述保留为设计与验收依据，不要求重复实现已经存在的身份、outbox、来源解析和分页功能。每次修改应以对应领域的协议不变量和必要回归为边界，避免只增加列表字段却未闭合写入、读取或删除语义。

整个目标完成必须同时满足：手机实际文件参与统一检索；同一文件多个位置不重复；上传与移除本机不丢分类；双端修改离线重连后收敛；检索结果可直接打开；手机安全释放后能恢复原件；关键失败场景有明确结果且无静默数据丢失。

后续阶段仍需明确目标规模与测试硬件、支持的 Android 系统范围、故障域识别方式及受保护文件夹的独立密钥域。30 天清理保留期和成员退役已有部分代码实现，其跨节点授权与并发安全缺口见 §11；涉及真实数据删除和权限语义变更时，应把最终策略落实到协议、产品交互、测试和文档。
