# Myliba 认证与授权操作说明

本文说明资源库和云层的统一认证。Hub、桌面客户端和 Android App 都需要更新到支持云层设备授权的版本。旧版云层客户端不能直接使用新版 Hub 的云层接口，须升级并重新配对。

## 一眼看懂

| 凭据 | 谁设置或获得 | 在哪里填写 | 用途 |
| --- | --- | --- | --- |
| 主人密码 `MYLIBA_WEB_PASSWORD` | Hub 管理者部署时设置，至少 16 字节，建议使用更长的随机 ASCII 字符串 | Hub 启动环境；Hub 网页登录；手机和桌面首次授权时输入 | 登录主人网页会话，给设备签发独立令牌 |
| 设备凭据 | Hub 在首次授权时自动生成 | 正常情况下无需手填 | 手机或桌面日后连接 Hub；授权的设备也用于云层直连 |
| 旧共享节点密钥 `MYLIBA_NODE_TOKEN` | 旧部署的管理者 | 旧 Hub 和尚未配对的旧客户端 | 至少 32 字节；仅供迁移，新部署无需设置 |
| 云层恢复密钥 | 云层初始化时生成 | 恢复或导入加密目录时使用 | 解密云层目录；与以上登录凭据不同，需单独备份 |

目前没有用户名、多主人账号或按文件夹划分的设备权限。输入正确的主人密码即可立即授权当前手机或电脑，不需要在 Hub 网页再次审批。正常配对时客户端申请浏览、提供资源和云层访问权限。Hub 网页的主人会话可以查看和撤销设备；普通设备会话不能管理设备。

## 1. 全新部署 Hub

在 VPS 上从**包含本认证功能的源码**构建：

```sh
pnpm install --frozen-lockfile
pnpm build
```

为 Hub 服务设置以下启动环境。示例密码和目录必须替换；持久化目录需要由运行 Hub 的系统账号读写：

```sh
export MYLIBA_MODE=hub
export MYLIBA_WEB_PASSWORD='replace-with-a-long-random-owner-password'
export MYLIBA_HUB_LISTEN=127.0.0.1:4318
export MYLIBA_HUB_DATA_DIR='/srv/myliba/hub-data'
./myliba
```

`MYLIBA_HUB_DATA_DIR` 可以不设；默认使用运行 Hub 的系统账号配置目录下的 `myliba-hub`。固定此目录并备份其中的 `auth.json`：它保存主人密码校验值、设备凭据的哈希、设备清单和登录会话。不要通过删除它来处理忘记密码或登录失败，否则原有设备授权会丢失。主人密码本身由启动环境提供，Hub 不把明文写入 `auth.json`。新部署只需设置这一份密码；无需设置 `MYLIBA_NODE_TOKEN` 或 `MYLIBA_CLOUD_TOKEN`。

用 HTTPS 反向代理公开 Hub，Hub 进程只监听回环地址。代理需保留 Host、Authorization 和 WebSocket 升级，并转发 `/`、`/api/`、`/node`、`/signal`；若使用单文件分享，还需转发 `/s/` 和 `/share/signal`。不要在公网把 `MYLIBA_HUB_COOKIE_SECURE` 设为 `0`。`MYLIBA_ICE_SERVERS` 是可选的 WebRTC 网络配置，不是登录密钥。默认只启用公共 STUN；蜂窝网络、对称 NAT 或严格防火墙常需要配置 TURN 中继，例如：

```sh
export MYLIBA_ICE_SERVERS='[{"urls":["stun:stun.example.net:3478"]},{"urls":["turn:turn.example.net:3478?transport=udp","turns:turn.example.net:5349?transport=tcp"],"username":"replace-with-turn-user","credential":"replace-with-turn-password"}]'
```

使用 TURN 时，WebRTC 数据会经过该 TURN 服务，但 DataChannel 仍由两端 DTLS 加密；若 TURN 与 Hub 部署在同一台机器，文件流量会占用该机器带宽。TURN 用户名和密码会随 ICE 配置发给已授权的连接端，因此应使用短期或专用 TURN 凭据，并通过 TLS 保护 Hub。TURN 服务自身的限流需要在 TURN 服务上配置，下面的 Hub 限流只作用于 Myliba 的 HTTP/WebSocket 内容回退。

资源库访问优先尝试 WebRTC；两端有可互通的 IPv6 时，ICE 可使用 IPv6 直连。如果家中 Go 资源节点有公网 IPv4，可在**节点进程**设置 `MYLIBA_RESOURCE_UDP_PORT_RANGE=40000-40031`，同时将路由器 UDP 40000–40031 映射到该节点，并开放主机防火墙。路由器位于运营商共享 NAT 后面时，单靠路由器端口映射无效。Android 资源节点目前没有固定 UDP 端口范围。日志会记录 IPv4/IPv6 候选类型，不记录实际地址。

WebRTC 无法连接时，已登录的 Web/App 用户可以经 Hub 获取资源文件、缩略图和视频数据。Hub 的内容回退默认全局限速 2 MiB/s，并限制同时传输数为 8；设置 `MYLIBA_HUB_RELAY_BYTES_PER_SECOND` 可调整每秒传输的原始内容字节数（范围 4096–1073741824）。此上限由 Hub 进程执行，反向代理仍需允许长时间响应；公开分享链接继续使用独立的 WebRTC 授权链路。

第一次启动时若已提供长度合格的旧节点密钥，Hub 会允许旧资源节点继续使用它，以便迁移；全新部署不需要它。

## 2. 授权家中电脑

1. 在家中电脑启动本地 Myliba，打开 `http://127.0.0.1:4317`。
2. 点页面上的 **服务端 → 添加服务端**，填写名称，以及 Hub 节点地址 `wss://你的域名/node`。
3. 在 **主人密码** 中输入 Hub 的 `MYLIBA_WEB_PASSWORD`，保存并连接。新流程不需要填写“旧版 Hub 的节点密钥”。
4. Hub 为这台电脑签发独立设备令牌；以后电脑自动用它连接。主人密码不会保存在电脑的 Hub 配置中，设备令牌保存在该电脑的本地 Myliba 数据库里。

本地 `127.0.0.1:4317` 页面本身没有 Hub 登录表单。云层也使用这台电脑已签发的设备凭据；无需再次填写密钥。一个本地客户端同时只连接一个选中的 Hub。

## 3. 授权 Android 原生 App，并让手机提供资源

1. 在 App 右上角选择 **家中**，打开 **家中资源库**，填写 Hub 根地址 `https://你的域名` 和主人密码，点连接。地址不要写 `/node`。
2. App 为这台手机申请独立设备令牌，并把令牌及浏览会话保存在 Android Keystore 保护的本机配置里。此后访问家中资源库无需再次输入主人密码；浏览会话过期时，App 会尝试用设备令牌恢复。
3. 要让别的客户端浏览手机文件，在 **本机** 选择手机文件夹并完成索引，然后到 **本机 → 来源 → 手机资源节点** 启动前台服务。已配对的手机不用再输入节点密钥。
4. 在 Hub 网页或另一台客户端的资源节点列表中选择这台手机。文件内容和预览需要两端建立直接 WebRTC 连接；看到索引不等于内容直连已经成功。

手机资源节点和 **云层存储节点** 是两个功能，使用同一台手机的设备授权。只运行存储节点的手机也可以在云层存储设置中输入一次主人密码配对。旧 Hub 没有设备授权接口时，App 可以退回旧网页登录；要使用新云层认证则必须更新 Hub 并重新配对。

## 4. 使用 Hub 网页

浏览器打开 `https://你的域名`，登录框只填**主人密码**，没有用户名或节点密钥。网页会话有效期为 30 天，并在 Hub 重启后保留；退出、过期或清除浏览器 Cookie 后，需要再次输入主人密码。Android App 的设备会话不会自动交给外部浏览器，因此另开浏览器仍要单独登录。

登录后从资源节点列表选择家中电脑或手机。Hub 负责身份验证、节点发现、信令和部分元数据；文件内容、缩略图与下载需要浏览器和选中节点之间的直接 WebRTC 通道。登录成功或能看到索引，不能单独证明文件内容可达。

如果只想给别人一个文件，在文件详情中创建有期限的单文件分享链接。收件人凭该链接访问指定文件，无需获得主人密码或整库权限；分享可撤销。

## 5. 查看、撤销和重新授权

主人登录 Hub 网页后打开 **设备授权**，可查看每台手机、电脑和独立存储节点，撤销某台设备。撤销会使该设备的浏览会话、资源节点连接和云层访问失效。要恢复使用，在该设备上重新输入主人密码配对即可。手机 App 中的“退出并撤销这台手机”也会撤销本机设备授权并停止手机资源节点与云层存储节点。

桌面本地页面的“断开服务端”或删除 Hub 配置只处理本地连接/配置；若要让丢失的电脑令牌在 Hub 上失效，还需在 Hub 网页撤销该设备。重新为同一台设备配对会签发新令牌，并让旧令牌失效。

## 6. 旧共享节点密钥迁移

旧部署更新 Hub 时，继续使用原来的 Hub 数据目录和原有 `MYLIBA_NODE_TOKEN`（至少 32 字节），让旧客户端不断线。不要因为采用上面的新部署示例就换到一个空的 `MYLIBA_HUB_DATA_DIR`。先更新 Hub，再分别在桌面和 Android 按第 2、3 节输入主人密码配对；确认它们作为资源节点在线，并实际打开一个文件。然后在 Hub 网页 **设备授权** 中关闭 **旧共享节点密钥**，最后从 Hub 启动环境移除 `MYLIBA_NODE_TOKEN`。

仅配置 `MYLIBA_NODE_TOKEN` 不会自动重新开启已经关闭的旧密钥模式。已登记的设备 ID 必须使用它自己的设备令牌，不能改用共享密钥。旧密钥模式关闭后，未配对的旧客户端需要升级并完成配对。

主人密码在 Hub 部署时设定后保持不变。如果启动环境中的密码与现有 `auth.json` 不一致，Hub 会拒绝启动。检查服务环境和数据目录，不要删除 `auth.json` 来绕过此校验。

## 7. 云层存储节点

桌面客户端按第 2 节重新授权后，自动使用该设备凭据访问云层。Android 在 **云层存储节点** 设置中填写 Hub HTTPS 地址；若这台手机已按第 3 节授权，可直接启动，否则输入一次主人密码。云层恢复密钥仍需单独备份，用于解密数据；可选的 OpenList 账号也仍由 OpenList 管理。

独立 Go 存储节点首次启动需要 `MYLIBA_HUB_URL`、`MYLIBA_CLOUD_PUBLIC_URL` 和临时的 `MYLIBA_OWNER_PASSWORD`（值为同一份主人密码）。配对后设备凭据保存到 `MYLIBA_CLOUD_DATA_DIR/device-credential`，后续启动无需再设置 `MYLIBA_OWNER_PASSWORD`。保护并备份此数据目录；撤销节点后须删除失效的设备凭据文件并用主人密码重新配对。云层客户端从 Hub 获取一次性短时票据交给直连节点，节点每次收到请求都向 Hub 核销票据；长期设备凭据不交给对方节点。Hub 离线时直连请求会暂时失败；加密块不经过 Hub。

旧版 `MYLIBA_CLOUD_TOKEN` 已不用于新版云层。更新 Hub、桌面客户端和存储节点后，分别重新配对，再从各服务环境移除旧云层密钥。

## 8. 常见现象

- App 已连 Hub 却仍要求输入主人密码：检查 Hub 是否已经更新到支持设备授权的版本，以及这台手机的授权是否被撤销。首次配对仍需输入一次。
- Hub 能显示节点和文件索引，但打不开文件内容：先检查两端 WebRTC 直连和节点运行状态。索引可经 Hub 传递，内容不会自动回退到 Hub 中转。
- Hub 重启后所有设备都要重新配对：检查是否换了运行账号、`MYLIBA_HUB_DATA_DIR` 或丢失了 `auth.json`。
- 节点断线后持续重试却收到 HTTP 401/403：Hub 已可访问，但拒绝了保存的节点凭据；这不是 WebRTC 或网络重连超时。先核对 Hub 是否使用原来的 `auth.json`，以及设备授权中该设备是否仍存在且未撤销。若旧认证数据可恢复，恢复后节点会继续重试；若确实失效，升级旧客户端并在桌面“服务端连接”或 Android“连接 Hub”中输入主人密码重新授权。不要删除设备上的本地文件或云层恢复密钥。
- 若 Hub 曾返回 502，恢复后改为 401，说明服务已重新响应，但授权状态与节点保存的凭据不匹配。检查 Hub 数据目录、旧共享密钥迁移设置和设备授权，再决定是否重新配对。
- 本地日志若出现 `legacy node credentials disabled`，表示 Hub 的“旧共享节点密钥”开关已关闭，并主动断开尚未按设备授权配对的旧节点。之后的 WebSocket 401 是认证拒绝，继续等待或重启旧程序无法恢复。升级客户端后用主人密码为每台电脑或手机分别配对；需要临时恢复旧节点时，可由主人在 Hub“设备授权”中暂时打开旧共享密钥，迁移完再关闭。云层新接口始终需要设备凭据，打开旧密钥不会修复云层 401。
- 手机蜂窝网络下 WebRTC 一直失败：蜂窝网络常使用运营商级 NAT。仅有 STUN 时两端不一定能建立 UDP 直连；配置 `MYLIBA_ICE_SERVERS` 中的 TURN 或 TURNs 服务，并更新 Hub、节点和 App 到支持 TURN 的版本。连接状态显示 TURN 时，数据经配置的 TURN 服务转发，内容仍在两端间加密。
