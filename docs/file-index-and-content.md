# 文件的统一索引与内容位置

## 一个文件，一份逻辑索引

每个入库文件有稳定的 `fileId`；原件内容变化时产生新的 `revisionId`。本机入库和加入云层只是同一文件的两种内容位置，不创建两个独立的文件索引。索引包含名称、类型、时间、标签、原件大小、缩略图和多尺寸视频清单，也包含以下可选位置：

- **本机位置**：当前节点的原件路径，以及缩略图、视频初始化片段和各尺寸视频片段的路径。一个客户端可以配置多个本机存储位置；同一内容项也可以在同一节点的多个位置有副本。每条位置记录 `nodeId`、稳定的 `storageId` 和路径，不能把甲节点的绝对路径当成乙节点可用的路径。
- **云层位置**：同一 `fileId + revisionId` 对应的加密内容块 ID、有序块清单、块位置与副本状态。只有文件加入云层后才存在，不能因为索引已同步就把本机原件自动上传。

索引首先保存在节点本地，随后与 Hub 和其他节点定期同步。同步时保留节点身份、存储位置 ID 与路径的对应关系；Hub 可以持有加密索引，但不接收原件、缩略图或视频片段的字节。其他节点看到本机路径时，只能知道该节点可能拥有内容，不能直接使用这个路径。配置存储位置、移动目录或介质离线时，应更新该节点的位置记录，而不是生成另一个文件索引。

```json
{
  "fileId": "stable-file-id",
  "revisionId": "source-revision",
  "metadata": {"name": "clip.mov", "kind": "video", "modified": "...", "tags": []},
  "original": {
    "size": 123,
    "locations": {"local": [
      {"nodeId": "A", "storageId": "source-d", "path": "D:/Media/clip.mov"},
      {"nodeId": "A", "storageId": "backup-e", "path": "E:/Backup/clip.mov"}
    ], "cloud": {"chunks": []}}
  },
  "assets": [
    {"assetId": "...", "kind": "thumbnail", "spec": "mobile", "size": 12,
     "locations": {"local": [{"nodeId": "A", "storageId": "preview-f", "path": "F:/Previews/clip.jpg"}], "cloud": {"chunks": []}}},
    {"assetId": "...", "kind": "video", "spec": "720p", "codec": "avc1...", "size": 80,
     "init": "...", "segments": [{"duration": 4, "partId": "..."}],
     "locations": {"local": [{"nodeId": "A", "storageId": "preview-f", "directory": "F:/Previews/clip-720p"}], "cloud": {"parts": []}}}
  ],
  "contentSize": 215
}
```

示例中的位置字段都是可选的。同一原件或派生内容在多个本机位置或云层同时存在时，它仍是一个内容项，不因副本数增加而重复计算文件体积。不同内容项可以分布在不同本机存储位置，不要求原件与缩略图同盘。`assetId` 由源修订、用途、规格和编码参数版本确定；播放 URL 是根据当前可用位置生成的临时访问地址，不是持久身份。

## 大小与读取

- `originalSize` 是原件字节数，用于原件下载的 `Content-Length`。
- `contentSize` 是原件、缩略图和所有已生成视频档位的明文字节数之和；同一内容的本机副本与云层副本只算一次。这是文件列表和详情显示的逻辑体积。
- `physicalBytes` 是各节点实际占用，包含云层加密开销、副本和历史修订，单独统计。

客户端查询某文件时，先枚举当前节点该内容项的所有本机位置，确认路径对应所请求的修订且文件仍可读取；有匹配位置就直接读本机，某个目录或磁盘离线时可尝试另一个本机位置。都不可用时，按云层块清单从可用存储节点读取、校验、解密。云层缺失但本机存在时，文件照常可用；本机位置失效但云层有副本时，回退到云层。读取云层内容时，原件、缩略图和视频片段都走存储节点直连或存储节点中继，不经过 Hub。

## 内容写入和同步

本机原件继续留在用户选定的路径。当前阶段可以应用数据目录作为缩略图和多尺寸视频的默认位置，并在同一索引中记录它们的 ID、规格、大小和具体本机位置。索引模型同时允许一个客户端配置多个存储位置，并为每项内容选择位置或保留多个本机副本；位置选择规则与本机目录布局留待后续设计。不要把尚未加入云层的本机文件强制复制成云层块。

文件加入云层时，原件和选择同步的派生内容拆成可验证的加密块；内容块先落盘并校验，再发布引用这些块的新索引版本。随后目录索引与 Hub、其他节点同步，块在存储节点之间复制或修复。新增视频档位时，只写该档位的内容与索引，不重传未变化的原件。生成中或失败的档位不出现在已发布索引中。副本不足只告警，不阻止已完成的本机写入。

## 当前实现和后续边界

`GET /api/resources/{id}/index` 合成本机资源、标签、缩略图、多档视频及云层内容清单，返回同一个 `fileId` 下的本机与云层位置。原件在原扫描目录；可配置多个派生媒体存储位置，新媒体写到选中的位置，已登记的旧位置仍可读取。默认位置是应用数据目录。旧缩略图和转码目录会在后台登记，未登记的历史缓存仍可按旧路径读取。

仅本机文件也会发布不含内容块的加密索引；扫描、标签变更和派生媒体生成后更新索引，节点运行时定期与 Hub 和其他节点交换加密目录。加入云层的文件把原件、缩略图和视频初始化片段及分段分别加密分块。后来生成的新档位只追加该档位的块。云层文件展示原件与派生媒体合计的逻辑体积。源文件与云层修订匹配时优先读本机；文件变化后不会把旧云层块挂到当前本机修订。视频播放器用 Media Source Extensions 按需获取片段。

尚未实现跨节点直接读取**只有对方本机位置、没有云层块**的文件；其他节点可以查询其索引，但该文件内容仍须在拥有原件的节点读取。一个资源在本机仍只有一条原件路径，多个原件扫描目录可以配置，但同一原件的多本机副本管理留待本机存储结构设计。新增媒体存储位置目前是选择后续生成媒体的默认目录，没有逐文件迁移或自动复制。浏览器列表与详情显示 `contentSize`，按大小排序仍按原件大小。历史加密目录记录和孤立内容块的回收尚未实现。
